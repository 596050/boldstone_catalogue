# Boldstone flat family directory proposal

Prepared 15 October 2026. No Dropbox changes were made.

## Requested layout

`Wall Sculptures / Family / [Member or pluralised combination] [Texture] [Colours or Surface Effects] [In Situ] / actual image files`

There is exactly one directory level after the family. There are no nested Images, Originals, Working, Process or Web Ready folders in the proposed tree. The existing source root is named `01 Wall Sculptures`; `Wall Sculptures` is the presentation label requested by the user, not an executed root rename.

## What is complete

The current recursive folder-only scan exhausted 16 pages and returned 422 unique stable folder IDs: 63 top-level groupings and 359 subdirectories. Fourteen existing folders are deeper than the requested leaf level. The current folder inventory and each source-to-target relationship are included.

The tree contains 347 proposed flat leaf names. This accounts for 359 current source subdirectories, two empty-direct-file wrappers to collapse, one separately identified video-only exception, 12 reductions from pooling equivalent subject groups, and three provisional groups for identified family-root files.

The complete folder scan is not a fresh exhaustive file census or a completed visual classification of every asset. Additional image-level distinctions may require splitting a proposed group. This is not an executable file-move manifest.

## Dagger / review flags

A dagger (†) after a TXT-tree line marks naming, identity, quantities, finish or provenance needing review. It is an annotation, not a character to put into the folder name.

74 proposed leaf names carry review flags. Unflagged SOURCE-LABEL rows are based on current source labels or clear text normalization. They are not universal visual verification, proof of a physical specimen, a sellable SKU or evidence that every contained image belongs to that label.

Unrecorded texture and finish terms are omitted rather than invented. Numbered member names are retained. `Diptych`, `Triptych`, `Quartet`, `9x9` and ambiguous `Two`/`Three` labels remain provisional where source wording does not establish exact members or repeat counts.

`In Situ` retains source context wording; it does not authenticate a real installation or a particular finish. Generated-image provenance must survive flattening and filename changes.

## Pooling directories is not deleting files

Process, detail and behind-the-scenes assets should sit directly in the appropriate named member/finish leaf once assigned, with those roles in filenames or the asset register, not additional directory depth.

Unidentified process/miscellaneous assets receive a flat provisional Unclassified leaf. These are temporary routing labels, not invented sculpture names.

Original and web-ready variants can share a subject leaf while retaining distinct filenames, asset IDs and source/derivative relationships. When pooling sources, preserve all content and test filename collisions. Matching target directory names do not authorize duplicate deletion.

All prior protected-keeper roles, completed-operation exclusions and unresolved holds must be carried into a separately approved file-level migration.
